# 个人同步空间后端

使用 Workers Free 和 SQLite Durable Objects，不依赖 R2、D1 或付费 Workers 计划。前端继续由现有 GitHub Pages 托管。

## 本地运行

在本目录运行：

```sh
npm ci
npm run dev
```

本地数据位于 `.wrangler` 目录，与线上隔离。不要使用 `--remote` 连接线上数据。`wrangler.jsonc` 的 `ALLOWED_ORIGINS` 只允许现有网站，以及 `127.0.0.1` / `localhost` 上 3090、3117 端口的本地预览。

联调前端时，将 `static/portfolio/sync-config.json` 的 `apiBase` 暂设为 `http://127.0.0.1:8787`，在项目根目录运行 `npm run build` 和 `npm run preview`，访问 `http://127.0.0.1:3090/portfolio/`。使用两个独立浏览器会话创建和加入空间。不要将本地 API 地址发布到线上。

## 端到端加密与配对

消息正文、设备备注、原文件名及文件内容在浏览器内加密，后端只存储和转发密文。Web Crypto 使用 AES-256-GCM，认证上下文绑定空间、消息发送设备与客户端消息 ID；附件每个分段分别认证。服务器仍可看到设备 ID、访问凭据、消息时间、密文大小和连接信息。消息时间、顺序和是否送达依赖中继；中继可以隐藏、重排或重放已有合法密文。此方案不提供逐条消息的前向保密；已获准成员可读取该空间仍保留的历史，撤销设备不会收回其已经保存的内容。网页代码及设备本身仍须可信。

保留单纯四位配对码，通过 `@serenity-kit/opaque` 的 OPAQUE 协议在两端认证并建立临时会话密钥，服务器不接收明文配对码、OPAQUE 注册记录或房间密钥。生成配对码的原设备须保持在线。配对码十分钟有效，原设备和加入设备都限制尝试次数；加入端每次提交配对码计一次尝试，不按候选空间重复计数，原设备仍保留每个邀请的尝试限制。有效期内其他设备获取同一加密邀请，显示同一个码；成功加入或移除设备会更新密钥并使当前邀请失效，后续配对需重新生成。全站最多同时开放 30 个配对空间，繁忙或码冲突时提示稍后重试。无法可靠区分同码空间时拒绝配对并提示重新生成，不猜测目标房间。

配对取消与最终入房按请求协调：取消先完成时阻止后续入房；已经提交时保留加密授权并返回实际结果，不把提交成功误报为取消成功。加入端遇到超时或临时网络错误，会使用原请求凭据核对结果，仍须用原 PAKE 会话及 nonce 验证授权。成功结果在本地会话保存后显式确认清理；用户主动中止时不会自动进入会话，若已经入房则注销新设备。

加入端使用本地不可导出的 AES 密钥，在 IndexedDB 中封装未确认请求、PAKE 临时状态及设备身份；sessionStorage 仅保留随机恢复索引和取消标记。刷新页面或网络恢复后沿用原请求、证明和 nonce 继续核对，不重复登记设备。本地恢复有效期为 20 分钟，过期记录在恢复检查时清除，实际恢复仍受服务器请求和授权有效期约束；主动取消的记录只用于注销收尾，已保存会话的记录只补确认，不重新加入。

设备拥有独立 P-256 ECDH 身份。加入设备通过 PAKE 接收房间密钥和已认证成员名单；加入和移除成员都更新房间密钥，向保留成员发送逐设备 ECDH/HKDF/AES-GCM 包装的密钥授权。加入成员和密钥轮换在房间内原子提交。设备仅接受已固定身份密钥的成员发来、匹配当前密钥版本的授权，设备列表不能自动建立密钥信任。离线成员在恢复后顺序领取、保存并确认授权；密钥变化期间旧密文不能作为新消息写入。

浏览器的 IndexedDB 使用不可导出的本地 AES 密钥封装会话及密钥，localStorage 只保留房间/设备 ID、访问凭据和本地保险库索引；草稿也以密文保存在 sessionStorage。清除浏览器数据会丢失本机解密密钥，需要另一台设备重新配对。

本版本与旧明文空间不兼容。首次部署的 v3 Durable Objects 迁移会删除旧 `PairingRegistry`、`SyncRoom`、`FileShard` 命名空间及其聊天、附件和设备配对，不备份；创建独立的 `E2eePairingRegistry`、`E2eeSyncRoom`、`E2eeFileShard` 命名空间。浏览器丢弃旧配对描述和旧明文草稿，用户须重新创建/加入空间。该删除仅在实际部署迁移时执行，本地构建和测试不会清理线上数据。

除文件下载外，返回内容都是 JSON；错误为 `{ "error": "错误码" }`。设备请求使用 `Authorization: Bearer <token>`，写入同时携带 `X-Sync-Key-Id`，凭据及密钥不得放进地址。`e2ee1.` 是房间密文，`pair1.` 是 PAKE 会话密文。

| 请求 | 用途 |
| --- | --- |
| `GET /health` | 服务入口、API 版本、发布提交及 Cloudflare 版本；数据库/维护详情见 `/v1/status` |
| `POST /v1/spaces`，`{ keyId }` | 创建设备端密钥对应的空间，返回独立设备访问凭据 |
| `GET /v1/pair/offers` | 读取有限数量的活动邀请 ID，不返回配对码 |
| `POST /v1/pair`，`{ requestId, requestToken, requests }` | 为候选邀请转发 PAKE 首轮请求 |
| `GET/POST/DELETE /v1/pair/:requestId` | 使用独立请求凭据轮询挑战、提交证明或取消；取消返回 `cancelled: true`，已入房返回 `cancelled: false` 及保留的加密授权 |
| `POST /v1/pair/:requestId/ack` | 本地会话保存成功后，使用原请求凭据确认领取并清理配对结果 |
| `POST /v1/spaces/:roomId/pair-code`，`{ offerId, secret }` | 发布或复用房间加密邀请 |
| `GET /v1/spaces/:roomId/pair-requests` | 原设备恢复未处理的 PAKE 请求 |

| `POST /v1/spaces/:roomId/pair-accept` | 提交会话加密授权，并原子加入设备和更新房间密钥版本 |
| `GET/DELETE /v1/spaces/:roomId/key-grants` | 领取/确认本设备的密钥更新 |
| `POST /v1/spaces/:roomId/key-rotation` | 向保留设备发布加密授权并更新密钥版本 |
| `GET /v1/spaces/:roomId/devices` | 返回当前设备及各设备的加密备注/身份资料 |
| `PATCH /v1/spaces/:roomId/devices/:deviceId`，`{ name }` | 写入加密资料；备注在设备端限制为 8 个 Unicode 字符 |
| `DELETE /v1/spaces/:roomId/devices/:deviceId` | 撤销设备及连接，并阻止旧密钥继续写入，直至保留成员完成轮换 |

四位码不是永久密码，只分享给信任的人；任何成功加入的设备拥有相同的空间管理权限。创建空间每 IP 每小时最多五次，配对每 IP 每十分钟最多 20 次，返回 `429` 时等待 `Retry-After`。

## 消息与实时连接

消息为 `{ id, clientId, deviceId, text, createdAt, attachment? }`，服务器的附件元数据只包含随机文件 ID、`application/octet-stream` 和密文长度，原名称、类型、明文长度及附件解密密钥放在加密消息正文中。`id` 是空间内递增整数，`clientId` 是客户端生成的 UUID v4，同设备重试同一个 `clientId` 会返回已有消息。设备端文字最多 10,000 个 UTF-16 码元，纯文字消息不能全为空白；带附件时文字可留空。后端校验密文格式、大小及密钥版本。每个空间最多保留 7 天、最近 500 条，删除消息时同步清理附件。已清空或超出保留范围的旧消息不再参与重试去重。前端 Enter 发送，Shift+Enter 换行；输入法选词不会触发发送。

提示音开关在同一浏览器的已打开标签页间同步，静音会立即停止当前提示音。同一空间、同一设备的标签页通过 Web Locks 协调通知水位和 750 毫秒节流，同一条新消息只响一次；未解锁声音或被浏览器拒绝播放的页面不占用通知水位，其他可播放页面仍可提醒。页面离开时使排队通知失效，恢复后可继续接收新提醒。

连接 `GET /v1/spaces/:roomId/socket` 并升级 WebSocket，地址中不携带凭据。浏览器使用子协议 `['sync', 'auth.' + token]`，后端在升级前校验凭据，正常连接按空间内设备分别限制为每十分钟 60 次；匿名或伪造凭据的连接共用每 IP 每十分钟 30 次的额度。服务器只选择 `sync` 子协议。升级后仍须在十秒内发送首帧 `{ "type": "auth", "token": "..." }`；首帧必须与升级时验证的设备一致。认证成功返回 `{ type: "ready", deviceId, messages, history, historyMode, pairing }`。首次只传最新 50 条，前端通过“加载更早消息”向前翻页。`history` 包含 `{ generation, oldestId, latestId, hasMore, continuationId, hasNewer }`。重连可带 `?after=:lastId&generation=:generation`，版本一致且游标仍在保留范围内时，每次最多传 50 条缺少的消息，`historyMode` 为 `append`；`hasNewer` 为真时继续以 `continuationId` 作为 `after` 分页补齐，实时广播不会跳过尚未补齐的消息；否则返回最新一页并以 `replace` 替换。历史清空、过期或容量淘汰都会更新版本，较早页面的过时响应不能重新加入列表。重连也从 Registry 读取最新配对码，不依赖设备本地保存的旧码。未认证连接不会收到历史、配对码或广播。

后续服务端广播 `{ type: "message", message, history }`、`{ type: "cleared", history, ... }` 或 `{ type: "history", messages, history, historyMode: "replace" }`。超过 500 条时，新增消息的 `history.oldestId` 和 `generation` 表示删除边界及新历史版本，不额外重发最近 50 条；客户端保留仍有效的已加载历史，并正常提醒新消息。过期及容量清理通过 `history` 同步最新一页，客户端替换已有列表。任一已配对设备调用 `POST /pair-code` 后，向同一空间的已认证连接广播 `{ type: "pairing", pairing }`，包括复用现有码时；该 HTTP 接口返回加密邀请，由设备解密得到配对码。客户端按 `expiresAt` 隐藏过期码，过期本身不主动广播；创建、加入、读取空间及重连的响应都会携带当前 `pairing`。Registry 只保存加密邀请，不保存明文配对码。设备加入、改名和撤销后广播 `{ type: "devices" }`，客户端可重新读取设备列表；被撤销的设备以 `4001` 断开，不再接收广播。客户端消息发送仍使用上述 HTTP 接口。需要保活时发送字符串 `ping`，运行时直接回复字符串 `pong`，不会唤醒闲置对象。客户端为建连、初始化消息、密钥同步和历史解密设置总计 30 秒的初始化期限，超时关闭旧连接并重试；超时后的异步结果不能写回新连接。客户端按指数退避并加入少量随机延迟重连；首次连接失败且确认空间已回收或凭据已撤销时，返回重新配对界面。

连接采用 Hibernation API。每个空间共用一个 Durable Object alarm，处理首次认证截止、最早消息满 7 天、未完成上传过期和待删除附件，无人打开网页时也能清理。期限没有变化时跳过重复的 alarm 写入；调度时读取实际 alarm，确保触发后的重新调度正常。alarm 实际触发时间取决于平台调度；读取、重连和发送前也会清除已过期消息。认证截止时间是十秒，超过截止时间的新认证帧始终会被拒绝。网络变化或后端重新部署会断开连接；客户端应重连并重新认证，使用新的 `ready` 历史恢复状态。

无效或已撤销凭据使用 WebSocket 关闭码 `4001`，客户端应清除该设备凭据并重新配对。超时或其他协议错误使用 `1008`。

## 文件与图片

每条消息可附一个任意格式文件，最大 `2 * 1024^3` 字节（2 GiB，界面标为 2GB）。客户端逐块读取文件，不把整个文件载入内存。每块明文最多 `8 MiB - 16` 字节，加上 AES-GCM 认证标签后密文块为 8 MiB；2 GiB 上限按原文件大小计算，后端额外允许认证标签开销。后端将文件存入多个 64 MiB 的 SQLite Durable Objects 分片；不使用 R2。上传状态按本次已确认的新增字节显示速度及预计剩余时间，恢复前已经上传的字节不计入测速。

仅配对新增设备时保留已上传分片，客户端用新房间密钥重新加密附件元数据后从原偏移续传；刷新页面后重新选择同一文件也可恢复。撤销设备或包含撤销的密钥轮换会取消旧上传，重新发送时使用新的附件密钥。

前端在系统窗口内预览附件：PNG/JPEG/GIF/WebP/AVIF/HEIC 图片支持缩放，PDF 按可见页渲染并纵向滚动，MP4/WebM/OGG 视频使用原生播放器按需读取。DOCX、XLSX/XLS/ODS/CSV/TSV 及常见文本文件在浏览器本地解析，不上传第三方文档查看服务。图片预览限 20 MiB，文档/表格限 25 MiB，文本限 2 MiB；表格在独立 Worker 内解析和格式化，主线程仅渲染可见行，显示当前工作表前 1,000 行、50 列和已有的公式缓存值，不执行公式。语言切换更新文档内提示并保留工作表及横纵滚动位置；加载失败后再次点击同一附件可重试。文档排版可能与原文件不同，旧版 `.doc` 等未支持格式或超过预览限制的文件仍可下载。关闭预览、清空历史或离开空间会释放预览资源并终止表格 Worker。

下表路径均以 `/v1/spaces/:roomId` 开头，除最后一项外需要设备凭据。

| 请求 | 返回或用途 |
| --- | --- |
| `POST /files/uploads`，JSON `{ clientId, name, type, size, text, fingerprint }` | `{ uploadId, chunkSize, receivedBytes }`；已完成的同一 `clientId` 返回 `{ message }` |
| `PUT /files/uploads/:uploadId/chunks/:index`，`application/octet-stream` | `{ receivedBytes }`；`index` 从零开始，末块除外均须为 `chunkSize` 字节 |
| `POST /files/uploads/:uploadId/complete` | 完整消息，新建为 `201`，重试为 `200`；完成后广播消息 |
| `DELETE /files/uploads/:uploadId` | `{ ok: true }`，取消当前设备的未完成上传 |
| `GET /files/:messageId`，也支持 `HEAD` | 鉴权后的密文文件字节流 |
| `POST /files/:messageId/download` | `{ ticket, expiresAt }`，取得本机下载凭证，同设备同附件复用有效票据 |
| `GET /downloads/:ticket`，也支持 `HEAD` | 可续传的文件下载，不需要 Authorization；ticket 24 小时内可重复使用，只返回密文 |

同设备对同一附件重复申请会返回已有票据及原到期时间，不延长有效期；临近到期一分钟时才换新票据。前端将下载与预览共用的票据缓存在当前会话内，并合并同时发起的申请；移除消息或切换空间时清除缓存。预览和下载前通过 HEAD 检查可用性，票据返回 401/404 时自动重新申请一次。下载使用浏览器原生文件下载，iframe 的 load 事件不代表下载失败；仍可再次点击下载重试。服务端每次下载和预览仍检查设备权限、附件存在及保留期限。

后端下载路径始终返回密文。前端在 `/portfolio/` 范围注册专用 Service Worker，使用仅在本机有效的随机能力 URL 流式解密，为 PDF、视频等提供明文 Range/HEAD，并用原始名称下载；能力只允许所属页面访问，关闭预览、离开空间或下载完成时释放。逐块读取并认证后才输出明文，不把完整 2 GiB 文件留在内存，不缓存到磁盘或第三方服务。下载失败会通知页面，下载路径不驻留已解密分块；失败或取消后保留 60 秒空闲续传窗口，期间活跃的 Range 读取不会被空闲计时器中断。过期时间同步到页面，Service Worker 重启后也不会恢复已过期能力。流完整交付与资源释放分别通知，不把流交付完成当作文件已写入磁盘；媒体预览继续复用独立的 Range 缓存。

上传前在 Worker 内对完整文件分块计算 SHA-256，再以附件独立密钥做 HMAC，服务端只接收加密绑定的指纹，不能用普通文件哈希直接猜测内容。同一 `clientId` 的指纹、随机名称、类型或大小不同会返回 `409 upload_conflict`；续传会重新完整校验文件，防止同名同大小但中间内容不同的文件混入原上传。失败后使用同一 `clientId` 重新初始化，再从 `receivedBytes` 继续顺序上传；同一块可以重试，内容冲突返回 `409 chunk_conflict`。进度字节数与块数在成功确认块时事务更新，重复块不重复计数；旧上传第一次恢复时从已有块记录补齐计数，以后不再逐块重复聚合整张记录。初始化、块上传和完成的可重试错误遵守 `Retry-After`（秒数或 HTTP 日期）；缺少该头时按指数退避，等待可取消。刷新页面会保留上传标识，重新选择同一文件并发送即可续传；上传期间可取消，保留输入的文字。未完成上传在最后活动 24 小时后回收。取消或清空后的上传不能继续完成。原文件名只保存在密文内，服务端文件名使用随机 UUID。空间成员可下载该空间的完整附件，但上传、续传和取消只能由原上传设备操作。

下载使用 `Content-Disposition: attachment` 和流式响应，浏览器直接保存文件，不先缓存整个 2 GiB。两种下载路径均支持单个 `Range: bytes=start-end`、`bytes=start-` 或 `bytes=-suffix`，返回 `206` 和准确的 `Content-Range`、`Content-Length`；无效、越界或多段请求返回 `416` 和 `Content-Range: bytes */总字节数`。`HEAD` 返回完整元信息和长度，不读取文件字节，也不处理 Range。文件返回稳定的 `ETag` 与 `Last-Modified`；`If-Range` 匹配时返回分段，失配时返回完整 `200`。流从所需分片偏移读取，每个分片最多一次 RPC，完整 2 GiB 原文件加认证标签后涉及 33 个存储分片。ticket 可在 24 小时内重试或继续下载，但设备撤销、消息删除或附件满 7 天后立即不可用。

## 存储清理

所有同步空间的文字、附件和进行中的上传共用一份容量预算。Registry 汇总自身、空间及附件分片的 SQLite 大小，并计入未完成上传预留容量。上传开始时已预留完整文件及开销，逐块传输只更新房间内的分片记录，不再每块触发 Registry 维护和容量回填；预留继续占用全局预算，在完成、取消、过期清理或每日复核时更新汇总。状态接口的 `storage.bytes` 是用于容量保护的汇总快照，`storedBytes` 和 `reservedBytes` 分别显示已存储及上传预留，两者相加等于 `bytes`；分片上传期间不会逐块更新全局快照。接近 4,800,000,000 字节时启动后台清理；新建空间和下一条文字消息预留 128 KiB，附件按完整文件及分片开销预留。新建空间在 Registry 内同步完成容量检查和预留，再创建房间并回填实际占用，容量不足时不创建数据库。先分批重新读取实际容量，避免旧记账触发多余删除；确认仍需清理后，本轮目标设为当前占用减去 3,000,000,000 字节，即通常从约 4.8 GB 降到约 1.8 GB。

后台按所有空间的已完成消息时间从旧到新清理，每批最多 100 条消息、每次 alarm 最多十批。先释放已标记删除的文件；淘汰批次遇到第一份附件即停止，分批释放它的分片后重新判断容量，避免顺带删除较新的消息。容量清理保护进行中的上传及其预留容量，未完成上传仅在取消或最后活动满 24 小时后回收。尚未达标则安排下一次。目标持久化，服务重新部署后仍可继续；总量已回到警戒线以下时允许继续发送。再次增长到 4.8 GB 后启动下一轮。清理删除消息及对应附件，保留设备配对凭据；若已无内容可删，仍被元数据占满，会返回 `507 storage_full`。达到警戒线或不足以预留完整附件时，返回 `503 storage_cleaning` 和 `Retry-After: 1`，稍后可重试。已有消息的重试直接返回原消息。删除也消耗 Cloudflare 免费写入额度，3 GB 是每轮目标，并不保证立即完成；每天 UTC 00:17 的 Cron 会分批复核已登记空间、修复过期清理 alarm，并恢复未完成的容量清理，以便日额度重置后继续。

Registry 对同一房间的操作按队列执行，跨房间等待不使用全局锁。跨房间写入前持久化预留容量，完成后原子替换为实际占用，防止并发上传同时通过容量检查。每日复核也校准中断操作留下的预留。单个房间维护较慢时，其他房间可以继续发送。

这里统计本项目登记的所有同步空间，不是账户实时剩余容量。Cloudflare 的 5 GB 免费存储由账户共享，其他 Worker 的存储不在此汇总中；账户每日请求、读写和执行用量可通过下述 Analytics API 连接查询，账户总存储余额尚未接入。容量清理阈值使用十进制 GB，单文件及分块大小使用二进制 GiB/MiB。

## 联络站存储与日志

桌面开始菜单的“控制面板”打开设置窗口，点击“联络站存储”进入同一窗口的二级页面，点击“上一级”返回。公开只读接口 `GET /v1/status` 不需要设备凭据或管理员密钥，进入详情时加载一次，查看期间每 15 分钟刷新，也可手动刷新；离开详情、最小化或关闭窗口后停止自动刷新。

状态接口只读探测应用数据，轮换抽样已登记房间及其已完成附件的现有分片，缺失分片不会被重新建表。每次 HTTP 查询只调用一次 Registry RPC；数据库诊断合并并发探测，成功结果在内存中复用至原检查时间后 15 秒，减少重复 SQL 和房间、分片 RPC，不增加持久化写入。失败探测不缓存，后续请求可立即重试；抽样只在重新探测时轮换。显示本项目存储和写入预留量、空间数、清理阶段及目标、最近维护时间和下次 alarm；不触发清理，也不返回房间 ID、消息、配对码、设备或下载凭据。维护从未成功时显示未执行，不会显示正常；超过 26 小时没有成功记录、待处理维护缺少 alarm 或 alarm 逾期一分钟以上会提示逾期。存储容量只统计本项目；账户存储与精确账单仍需账户持有人登录控制台查看，释放存储不会恢复当日请求、读写或执行额度。

### 账户每日额度监控

控制面板也可显示整个 Cloudflare 账户当天的 Workers 请求、Durable Objects 请求、SQLite 读写行数和执行时长。后端通过官方 GraphQL Analytics API 获取 UTC 当天 00:00 至查询时刻的账户汇总，不按本项目过滤；额度在 UTC 00:00 重置。统计属于平台可能采样、延迟的估算，不能作为精确账单，也不代表达到额度前一定可用。Durable Objects 的 `hibernation` 入站 WebSocket 消息从 invocations 数据集读取，普通 WebSocket 入站消息从 periodic 数据集读取，分别按 20 条折算 1 次请求后相加，其余请求类型正常计数；执行时长保留官方 `duration` 的 GB·秒单位。免费额度参考值分别为每日 100,000、100,000、5,000,000、100,000 和 13,000 GB·秒；达到 80%、95%、100% 会提高提示级别。

`wrangler.jsonc` 中的 `CF_ACCOUNT_ID` 是账户标识，不是密钥。启用查询还需账户持有人创建仅限该账户、具有 Analytics Read / Account Analytics 只读权限的 API Token，然后在本目录执行以下命令，按提示输入；不要把 Token 写进配置、前端或 Git：

```sh
npx wrangler secret put CF_ANALYTICS_TOKEN
```

本地隔离调试可以使用未跟踪的 `.dev.vars`；测试自带虚构响应，不需要真实凭据。缺少凭据时返回 `dailyUsage.status = "not_configured"`、`available = false`、`metrics = null`，不会显示成用量为零。API 返回错误时，不向公开接口或日志透出原始错误及请求内容。

Registry 仅在状态接口被访问时按需采集账户额度，合并并发查询，将成功结果缓存在内存和持久存储中 15 分钟；失败结果缓存 1 分钟，避免公开刷新连续请求 Analytics API。不设置后台额度采集 Cron，原有 UTC 00:17 的每日维护只执行清理复核。同一天查询失败时，可以展示最近成功值，但标为 `stale` 并保留原查询时间；跨过 UTC 午夜后不会把昨日结果显示为今日用量。监控故障不影响 `/health`、数据库探测或清理任务。

`GET /v1/status` 增加 `dailyUsage`：`status` 为 `ready`、`stale`、`not_configured` 或 `unavailable`；`day` 为查询对应的 UTC 日期，`checkedAt` 为最近成功时间，`resetsAt` 为下次 UTC 午夜。`metrics` 中的 `workersRequests`、`durableRequests`、`rowsRead`、`rowsWritten`、`duration` 各含 `used`、`limit`、`level`，后者为 `normal`、`warning`、`critical` 或 `exceeded`。公开响应仅包含汇总用量，不包含账户 ID、Token 或 Worker 名称。存储容量仍按本项目统计，不能用账户每日请求用量推算存储余额。

配置开启 10% 采样的 Workers Logs，关闭默认 invocation logs，避免记录下载票据所在的完整 URL。应用错误日志只包含固定路由类别、HTTP 状态、耗时和通用错误码；不记录请求体、原始异常、凭据、配对码或票据路径。维护失败记录时间并产生 `sync_maintenance_error`，平台可重试 alarm。

## 完整大文件本地验收

在本目录运行 `npm run test:large-transfer`，使用独立临时目录和本地 Miniflare，不连接线上、不使用真实文件。测试实际加密并上传完整 2 GiB，使用 257 个至多 8 MiB 的密文块，约 512 MiB 后重启运行时，检查重复块计数与续传；完整流式慢读下载后核对 SHA-256，再检查跨分片 Range、末段续传以及下载中撤销设备。结束时删除测试数据库。需要至少 7 GiB 可用临时磁盘，因耗时和磁盘开销单独执行，不加入日常单元测试。

本次加密版本机验收已完整通过：原文件 2,147,483,648 字节，257 个加密分段，解密后的下载 SHA-256 为 `2ae17de75eba49fa4c37e88ee77109f7d7d02663d1923537e38715c2de9a4dbb`，约 78 秒。Node 进程峰值 RSS 约 358 MiB（不包含 workerd 子进程）；这是隔离的本地结果，公网吞吐仍取决于网络和 Cloudflare 免费额度。此长传用真实 PAKE 加入另一台设备，再验证该设备下载及中途撤销；浏览器内预览/下载桥接由独立 Chromium/WebKit 测试覆盖。

日常空间刷新和每日轮扫也会回收闲置空房间：必须没有设备、保留消息、文件、上传记录或分片，且没有仍有效的配对码。最后一台设备退出后无法再完成需要原设备在线的加密配对；维护会回收过期邀请和空房间。符合条件时删除房间 SQLite、Registry 容量记录及其过期配对码。同一房间的配对加入和回收在 Registry 内串行执行，已回收房间的迟到请求不会重新创建数据库。仍有内容或待清理分片的空间先按现有保留期及分批规则处理。

仍留有旧设备凭据的废弃空房间，在超过 7 天无认证活动、没有在线的已认证设备、没有有效配对码，且所有消息、附件、上传和分片都已清理后，也会在维护时回收。活动记录每小时最多写一次，并为回收增加一小时宽限；有效 HTTP 鉴权、设备加入和合法下载会更新活动，已认证的长连接断开时也会补记活动。既有空间首次升级从当前时间开始计时，不会因缺少旧活动记录被立即回收。回收后的旧凭据失效，重新使用需要创建或加入空间。

设备凭据按每台设备独立计算：连续 7 天没有有效 HTTP 请求、下载或已认证 WebSocket 心跳即失效。活动时间每分钟最多持久化一次，每次请求仍检查设备是否存在及过期。过期请求不能续期；维护和房间 alarm 会删除旧设备、其下载票据并取消未完成上传，已完成的共享消息和附件仍按现有保留规则处理。正常使用自动续期，不需要每 7 天重新配对；既有设备首次升级获得完整 7 天宽限。设备表只保存凭据哈希及活动时间，不保存明文凭据。

## 上线配置

网站两种入口均通过早期 CSP meta 限制脚本和资源来源：只运行本站脚本，禁止内联脚本、字符串求值、插件对象、base URL 覆盖和原生表单提交；API、WebSocket、邮件和卫星数据仅放行实际使用的来源。HEIC 使用 CSP 兼容转换器；保留 WebAssembly 编译与界面必要的内联样式。GitHub Pages 不提供自定义响应头，因此采用 meta 策略，不宣称它能限制外部网站嵌入（frame-ancestors 需响应头支持）。

后端地址为 `https://portfolio-sync.li2096870763.workers.dev`。更新后端时，先提交本次发布内容，在本目录运行 `npm run deploy`。脚本要求工作区干净，先运行后端测试和打包检查，检查 Cloudflare 登录，再部署并注入当前完整 Git SHA 为 `RELEASE_REVISION`；部署后检查 `/health` 返回的服务名、API 版本、提交 SHA 和 Cloudflare 版本 ID，失败会以非零状态退出。使用兼容 Workers Free 的 `new_sqlite_classes` 迁移，不开通付费计划。仓库内 `static/portfolio/sync-config.json` 的 `apiBase` 指向该 HTTPS 地址，修改前端后仍需构建并发布网站。协议有不兼容改动时，同时把本目录 `src/api-version.js` 的 `API_VERSION` 和 `sync-config.json` 的 `apiVersion` 加 1，先部署后端再推送前端；CI 发布 Pages 前会用 `npm run check:sync-api` 检查线上 Worker 版本，落后则停止发布。

GitHub Pages 发布后，在仓库根目录运行 `npm run verify:release -- <本次完整提交SHA>`。验证器只发 GET 请求，不创建空间或消息；除核对后端版本及加密版本外，还逐字节比较线上个人主页 HTML、后端配置、主 JS、主 CSS 和解密 Service Worker 与本地 `docs/` 构建结果（`docs/` 不纳入 Git，验证前先在仓库根目录运行 `npm run build`），防止后端成功而前端仍是旧版。单独验证后端可在本目录运行 `npm run verify:release -- <本次完整提交SHA> --backend-only`。`/health` 可访问、CI 通过或部署命令成功都不替代这一步。

前端只从这个静态配置读取后端地址；不要通过查询参数接受其他 API 地址，避免访问者的设备凭据被发送到陌生服务。Cloudflare 登录由账号持有人完成，不把 API token、设备凭据或 `.dev.vars` 提交到仓库。
